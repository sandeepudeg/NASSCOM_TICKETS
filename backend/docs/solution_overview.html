Solution Overview

Tickets Folder Feature

Self-hosted AI ticket routing & resolution with zero external LLM calls, security-first defaults, and observability baked in.

Approach

  • End-to-end stack: React 18 UI → Traefik → FastAPI → Ollama/pgvector/MinIO, all runnable via Docker Compose.
  • Strict layering (api → services → repositories → ml → schemas) keeps contracts clean and testable.
  • Safety pipeline: Presidio PII scrub → embeddings → LLM classify; confidence gating triggers RAG or escalation.
  • Observability-first: Prometheus metrics, OTEL traces, structured logs with SLO targets.

Unique Selling Proposition

  • 100% local inference (Ollama) → zero SaaS LLM cost and no data egress risk.
  • Security by default: PII scrub before embeddings, AES-256 at rest, RBAC + audit log, rate limits.
  • Human-in-loop: built-in escalation queue and override feedback for retraining—reduces misroutes.
  • Domain adaptability: swap taxonomy/models and vector store (pgvector↔Qdrant) without code changes.
  • Ops-ready: metrics/traces/logs and SLOs included, not bolted on.

Key Flows

  • Ticket classify: JWT-validated request → scrub → embed → LLM category+confidence → if ≥ threshold run ANN search + LLM resolution suggestion; else escalate; persist ticket + audit entry.
  • Foldering: CRUD with optimistic locking; bulk assign up to 100 tickets in one transaction with HTTP 207 on partial failure.
  • Pattern alerts: scheduled clustering on recent tickets to surface recurring issues; actions to snooze/ack/dismiss.

Dependencies & Assumptions

  • Docker 24+ & Compose v2; Python 3.10+; Node 18+; Ollama models (mistral:7b-instruct or phi3-mini/gemma2b).
  • PostgreSQL 14+ with pgvector; MinIO; Keycloak/Authentik for OAuth2/OIDC.
  • Hardware: ≥8 GB RAM (16 GB recommended) and ~20 GB disk for models/data.
  • Secrets provided via .env: JWT, encryption keys, API base URLs; optional feature flags for multi-folder, Qdrant, PII toggle.
